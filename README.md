# VPS 下行测速

Windows 本地网页工具，使用 Go 标准库和外部 iperf3 测量 VPS 到本机的下行吞吐。当前主实现为 `main.go`，运行入口为 `start-web.bat` 或 `vps-speedtest.exe`。

当前版本：2.2.0，构建目标为 Windows x64。仓库包含源码、测试、构建脚本和示例配置；可执行程序、第三方运行依赖、真实节点配置及测速记录不纳入版本管理。

## 从源码开始

1. 在 Windows 上安装 Go 1.19 或更新版本，确保 `go` 在 PATH 中；编译使用纯 Go 标准库，无需额外 Go 包。
2. 在项目目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1`。脚本先测试和静态检查，再生成 `dist\vps-speedtest.exe`。
3. 首次使用时，将生成的 exe 复制到项目根目录，与 `start-web.bat` 放在一起。更新已有程序时，先退出服务并保留旧 exe。
4. 准备 Windows x64 版 iperf3，把 `iperf3.exe` 和该发行包需要的 DLL 一起放入 `iperf3` 子目录。依赖查找规则见下文。
5. 按需将 `nodes.example.json` 复制为 `nodes.json`，替换为自己的服务端地址；已有配置请保留。示例中的 `example.com` 仅用于说明格式，不能直接测速。缺少配置时也可在页面手动输入目标。
6. 双击 `start-web.bat` 启动。

仅运行编译好的程序无需安装 Go、Node.js。Node.js 只用于执行仓库中的前端测试。所有运行文件放在可写目录中，保持 exe 与配置、数据的相对位置。

## 使用

1. 双击 `start-web.bat`，浏览器打开 `http://127.0.0.1:8123/`。
2. 选择节点或输入 IP / 域名。服务端需要已运行 `iperf3 -s`。
3. 端口范围 1–65535，时长 1–300 秒，并发流 1–32。留空默认分别为 5201、10、1。
4. 测速固定使用 `-R -O 3 -J`，总等待时间包括 3 秒预热，程序超时为时长加 20 秒。
5. 页面分别显示测速结果与记录保存状态。“历史图表”和“退出服务”位于顶部吸顶操作栏，滚动长记录时仍可使用。关闭标签不会退出服务；有测试时退出会提示取消并记录失败。

所有配置和数据以 **exe 所在目录** 为准。请放在可写目录。主目录的 `speedtest_log.csv` 保留既有数据，成功和失败均追加；参数无效、忙碌或会话拒绝不会写入测试记录。首页和图表仍只显示成功记录。完整有效结果为零吞吐时显示 `0 Mbps` 并记录成功。

再次运行程序时，仅在端口上确认为同版本本工具才打开已有服务。其他程序或旧版本占用端口时会提示错误，请先退出冲突程序。启动错误同时尝试写入同目录 `startup-error.log`。

## 在网页删除记录

- 单条删除：点击记录右侧“删除”，核对弹出的时间、目标和速度，再点“确认删除”。
- 批量删除：勾选左侧复选框，再点“删除所选”。“本页全选”只选择当前页，最多 100 条；取消确认不会删除。
- 较早记录：使用“上一页 / 下一页”，每页 100 条；翻页或刷新会清空选择。记录管理栏也会吸顶。
- 每次删除前，程序先把原始 CSV 完整备份到 `backups/deletions`，再移除所选记录，其他记录与表头保持原始字节。备份失败则不删除。
- 误删后可点“撤销上次删除”。它只适用于同一页面、本次服务运行期间的最后一次删除，且删除后没有新测速记录或其他文件变更；刷新页面或重启后该按钮不可恢复旧操作。原始备份仍保留，不自动清理。
- 如果提示“记录已变化”，点“刷新记录”后重新选择，避免误删另一页或另一时间点的数据。
- 当前页面仍仅展示和删除成功记录；隐藏的失败记录会保留。已打开的图表页需刷新，或重新打开图表查看删除后的历史。

需要从旧备份恢复时，先退出服务并另存当前 CSV；不要直接覆盖包含新记录的当前文件。如需保留删除后的新记录，应比较合并，不能整文件回滚。

删除功能开发时已通过 16 组 Go 测试、静态检查、前端回归及隔离网页删除/撤销验收，测试没有删除正式记录。机器专用验收副本不随源码仓库发布。

## 运行依赖与配置

iperf3 查找顺序：同目录 `iperf3.exe` → `iperf3\iperf3.exe` → PATH。放入后需重启本工具。依赖 DLL 应与 iperf3.exe 一起保留。

当前版本曾使用 Windows 版 iperf3 3.1.3 和 `cygwin1.dll` 通过本机回环验证，未检查全部公网节点的兼容性。第三方依赖需单独准备，使用和分发时保留其许可证与来源说明。

`nodes.json` 必须是合法 JSON 数组，不能有尾逗号；名称和目标必填，端口可省略，默认 5201。同一规范化地址及端口不能重复。支持 IP（含 IPv6）和 ASCII 域名；国际化域名请使用其 ASCII 编码。配置解析失败会在界面显示，不会静默当成空配置。

```json
[
  { "name": "示例节点", "host": "example.com", "port": 5201 }
]
```

图表沿用 ECharts CDN，仍需要网络加载，尚未离线化；加载失败时会明确提示，统计摘要仍可使用。

## 历史图表

测速首页与历史图表使用统一的配色、卡片、按钮及页面宽度。桌面上测速参数与结果并排显示，窄屏自动上下排列；常用操作和记录管理栏保持吸顶。

版本 2.2.0 的图表页支持节点、并发流及全部历史 / 最近 7、30、90 天筛选。时间范围按本机当前时间计算；没有匹配记录时显示空状态，不伪造曲线。

上方统计卡片显示筛选后的成功测试次数、最新一次、等权平均下行和峰值。统计口径不随图例隐藏或图表缩放变化。混合多个节点时，平均值是所选测试记录的算术平均，不代表单个节点性能。

每条曲线由“地址与端口 + 并发流”唯一确定，同名节点不合并，不同并发流不混成一条线。标签显示节点名及并发流，悬停标签查看地址，勾选可显示或隐藏曲线。“显示全部曲线”恢复图例，“重置缩放”恢复时间范围。曲线仅用直线连接实测点，不表示连续监测或插值测量。

悬停或轻点数据点查看节点、地址、时间、并发流、Mbps 与 MB/s。拖动底部滑块缩放；桌面也可按 Ctrl 滚轮缩放。删除记录后点击“刷新数据”读取最新历史，刷新保留仍有效的筛选项。

## 构建与验证

需要 Windows Go 工具链（使用 CSV 字节偏移接口，要求 Go 1.19 或更新）。本项目只有标准库，没有 go.mod，所有命令显式指定源文件。

```powershell
# 优先使用本项目 .tools\go\bin\go.exe，否则查找 PATH
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1

# 也可以指定已安装的 Go
.\build.ps1 -GoPath 'C:\Program Files\Go\bin\go.exe'
```

脚本依次运行 `go test -count=1 main.go main_test.go`、`go vet main.go main_test.go`，再以 `-trimpath -ldflags '-H=windowsgui -s -w'` 构建 `dist\vps-speedtest.exe`。默认不覆盖根目录正式程序。环境变量在脚本结束时恢复。

修改内嵌 JavaScript 后，另执行 `node frontend_test.cjs`。该测试使用简化 DOM 校验状态、参数快照和退出竞态，不能代替真实浏览器视觉验收。

修改图表后执行 `node chart_test.cjs`，并检查真实浏览器的筛选、图例和窄屏布局。

请将待验收 exe、节点配置和 iperf3 依赖放入独立目录，避免测试写入正式日志。`go run main.go` 的临时 exe 目录会改变数据位置，不建议用来检查生产数据。

后端测试使用临时目录和模拟 iperf 子进程。真实测速验收请使用独立运行目录，优先连接本机回环服务，不要让测试写入正式历史文件。程序已验证本机回环、取消退出、记录删除与撤销，以及桌面和 375px 窄屏页面；跨机器兼容性需在目标机器验证。

## 当前接口

所有接口限制准确的 Host `127.0.0.1:8123`；有 Origin 时须为 `http://127.0.0.1:8123`，拒绝跨站来源。无 CORS 授权。变更接口还要求每次进程启动生成的 `X-App-Token`，通过同源 `/session` 获取；页面刷新可恢复重启后的会话。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /`、`GET /chart` | 首页和图表 |
| `GET /health` | 应用标识 `vps-speedtest-local`、版本 `2.2.0`，用于启动身份探测 |
| `GET /session` | 返回本进程会话 token；不写入磁盘 |
| `GET /nodes` | 返回已验证、规范化节点数组；缺文件为 `[]`，错误为 HTTP 500 |
| `GET /data` | 保留原字段并增加 `id`（文件 SHA256 + 记录序号）；成功记录；损坏记录警告通过 URL 编码的 `X-Data-Warning` 头返回 |
| `POST /test?host=...&port=...&t=...&P=...` | 参数校验后接受测试，需 token；返回 `ok/mbps/err/saved/saveError/t`，其中 err、saveError 仅在有值时出现 |
| `POST /quit` | 需 token；取消测试、等待日志处理并关闭服务；响应表示已接纳退出请求 |
| `POST /history/delete` | 需 token，JSON `{"ids":["..."]}`；1–100 条当前快照记录；返回 deleted、backup 和 undo；数据已变化或 CSV 损坏时返回 409 |
| `POST /history/undo` | 需 token，JSON `{"id":"上次删除返回的 undo"}`；核对当前文件和备份哈希后恢复；不接受客户端指定文件路径 |

错误方法 405，会话/来源错误 403，参数错误 400，已有测试 409，正在退出 503。被接纳的测速以 HTTP 200 返回业务结果，`ok` 代表测速是否成功，`saved` 代表记录是否确认保存。CSV 未确认保存时不要把结果视为已持久化。

`/ping`、`/bye` 已移除，未知路径返回 404。CSV 七列表头保持为：`测试时间,目标,端口,时长(s),线程,下行Mbps,状态`；仅界面将“线程”改为“并发流”。

## 回滚

先在页面显式退出服务，再恢复更新前另存的 exe，或使用对应源码版本重新编译。节点配置、CSV 和删除备份独立保留；程序回滚时不要覆盖已有测速记录。
